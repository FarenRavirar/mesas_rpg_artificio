# Bug Report: Exclusão por admin na página da mesa usa endpoint de mestre

**Type**: Implementation drift  
**Severity**: High  
**Feature**: `specs/007-exclusao-mesa-sem-popup/`  
**Reported**: 2026-04-29  
**Status**: Patched  
**Patched**: 2026-04-29

## Description

Após deploy Beta da feature 007, a confirmação inline da página da mesa acionou `DELETE /api/v1/gm/tables/c8e809d7-6881-475f-ba01-9d9b0cc29185` e recebeu `404 Mesa não encontrada.`.

O erro ocorreu porque `MesaPage` permite gerenciamento quando o usuário é dono da mesa ou admin, mas `TableActionPanel` chamava sempre o endpoint de mestre. Para admin gerenciando mesa que não pertence ao próprio perfil de mestre, a rota `/gm/tables/:id` não encontra a mesa por causa do filtro de ownership. A rota correta nesse contexto é `/api/v1/admin/tables/:id`.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 - Confirmar exclusão dentro da página.
- **Affected requirements**: FR-008, FR-009, FR-010 e FR-012.
- **Gap identified**: A especificação exigia preservar permissões, mas não explicitava que a página/preview deve escolher endpoint conforme contexto de gestão: mestre dono usa rota GM; admin usa rota admin.

### plan.md
- **Affected sections**: Technical Context, Project Structure e Phase 0 Research Summary.
- **Impact**: O plano já listava os dois endpoints, mas `TableActionPanel` precisava receber o contexto de exclusão para selecionar a rota correta.

### tasks.md
- **Affected tasks**: T007, T010 e T012.
- **False completions**: T007 foi marcada completa sem validar o caso admin na página/preview da mesa.
- **Missing tasks**: Adicionar validação de seleção correta de endpoint por contexto de permissão na página/preview.

## Root Cause Analysis

A implementação substituiu o diálogo do navegador por confirmação inline, mas moveu a chamada de exclusão da página/preview para dentro de `TableActionPanel` sem passar o contexto que diferenciava mestre dono e admin. Como `canManage` em `MesaPage` cobre ambos os casos, o componente ficou visualmente disponível para admin, porém operacionalmente preso ao endpoint de mestre.

## Recommended Fix

1. Atualizar os artefatos da feature 007 com a regra de seleção de endpoint por contexto.
2. Fazer `TableActionPanel` aceitar o escopo de exclusão (`gm` ou `admin`).
3. Passar `admin` a partir de `MesaPage` quando o usuário autenticado for admin.
4. Validar build e busca final por pop-ups de exclusão.
